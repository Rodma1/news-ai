# PRD: AI 资讯聚合与智能摘要网站（news-ai）

## 1. 需求背景

AI 领域发展极快，新模型、新产品、新论文每天大量涌现，信息分散在科技媒体、技术社区和社交平台中。手动浏览效率低、噪音大，容易错过重要进展。用户要做一个公开访问的 AI 资讯网站：每天自动采集高质量 AI 文章等信息，同时开放写入接口接收本地任务推送的内容，再通过大模型进行整合（摘要、分类、日报、问答），让访客用最少的时间掌握当天 AI 领域全貌。网站后续计划投放广告变现，因此面向公众访客设计；首期不实现广告位，界面按最佳交互体验打磨，做到好看实用。

## 2. 目标与价值

**目标：**
- 每天定时自动从 3 类信息源采集 AI 相关文章：主流科技媒体 RSS（TechCrunch、The Verge、机器之心、量子位等）、技术社区/学术源（Hacker News、arXiv、Hugging Face、GitHub Trending 等）、社交平台（Reddit r/MachineLearning 等）
- 每篇文章自动生成中文摘要、分类标签、重要性评分（1-5）
- 每天自动生成一份「AI 日报」：Top 重要事件 + 趋势总结
- 支持基于已采集内容的智能问答
- 开放新闻写入 API（Token 鉴权），支持用户在本地跑任务向网站推送文章
- 面向公众访客开放浏览，界面按最佳交互体验打磨（好看实用），为后续广告投放变现做准备
- 全流程自动化，无需人工干预

**价值：**
- 将每天 1-2 小时的信息浏览压缩到 10 分钟
- 不遗漏重要 AI 进展，重要性评分帮助快速聚焦
- 形成专属 AI 知识库，可回溯、可检索、可提问
- 网站积累流量后具备广告变现潜力

## 3. 术语 / 角色定义

- **信息源（Source）**：配置的采集渠道，如 RSS 地址、社区榜单页面
- **采集（Crawl）**：定时抓取信息源获取新文章的过程
- **AI 处理（Enrich）**：调用大模型 API 生成摘要/标签/评分
- **日报（Daily Digest）**：每天自动生成的 AI 事件精选与趋势总结
- **访客（Visitor）**：公开访问网站的普通用户，免登录浏览
- **管理员（Admin）**：网站所有者（用户本人），通过账号密码登录后台
- **写入 API（Ingest API）**：开放给本地任务的新闻写入接口，Bearer Token 鉴权

## 4. 适用范围

- 适用：部署在用户云服务器上的公开 Web 网站，访客免登录浏览，PC 浏览器优先、兼容手机浏览器
- 适用：RSS/网页采集 + 本地任务 API 推送 + 大模型 API 处理 + 前后端展示的完整闭环
- 不适用：访客注册登录、UGC 内容（评论/投稿）等社区功能

## 5. 非目标 / 超出范围

- 不做访客注册/登录体系（访客免登录浏览；仅后台管理有账号密码登录保护）
- 不做文章全文托管/转载（仅存标题、摘要等元数据，阅读时跳转原文链接）
- 不做本地大模型推理（服务器仅 1.7G 内存，AI 处理全部走云端 API）
- 首期不做移动 App / 小程序
- 首期不做广告位实现与广告平台接入（界面按最佳交互体验设计，为后续广告预留扩展空间）
- 首期 Twitter/X 与 YouTube 采集仅尽力而为（无官方 API 时不保证可用）

## 6. 功能需求

- **FR-1 信息源管理**：内置默认信息源（RSS：TechCrunch AI、The Verge AI、机器之心、量子位；社区：Hacker News、arXiv cs.AI/cs.CL、Hugging Face Daily Papers、GitHub Trending；社交：Reddit r/MachineLearning）。管理页支持添加/编辑/禁用信息源，并展示每个源最近一次采集状态与时间。
- **FR-2 定时采集**：每日定时触发（默认 07:00 / 12:00 / 20:00，可配置）。RSS 用 XML 解析，网页榜单用选择器解析。**所有 HTTPS 抓取必须通过 subprocess 调用系统 curl 实现**（服务器 Python 3.11 缺 _ssl 模块）。
- **FR-3 去重与入库**：按 URL 规范化（去除 utm 等跟踪参数）+ 标题相似度去重。文章字段：标题、来源、原文链接、发布时间、原文摘要/正文片段、采集时间、AI 摘要、标签、重要性评分、AI 处理状态（pending/done/failed）。
- **FR-4 AI 处理管道**：新文章入库后异步调用大模型 API，生成：中文摘要（≤120 字）、分类标签（大模型/多模态/Agent/开源/硬件/政策/论文等）、重要性评分（1-5）、涉及实体（公司/模型名）。失败自动重试 3 次。API Key 通过 .env/环境变量配置，禁止硬编码。
- **FR-5 每日 AI 日报**：每天采集批次完成后，由大模型汇总当日已评分文章生成日报：今日 Top 5 重要事件（一句话解读 + 原文链接）、分类速览、趋势总结（≤300 字）。日报按日期存档，可回看。
- **FR-6 资讯浏览页（公开）**：面向所有访客开放、免登录。文章列表支持按时间/重要性排序，按标签/来源/日期筛选，标题关键词搜索。列表项展示：标题、来源、时间、AI 摘要、标签、评分星级。点击跳转原文。页面做基础 SEO（title、description 服务端输出），保证可被搜索引擎收录。
- **FR-7 日报页**：默认展示最新一期日报，支持按日期浏览历史日报。
- **FR-8 智能问答**：输入自然语言问题（如「本周有哪些大模型发布？」），系统先对本地文章库做关键词/标签检索，命中内容交给大模型归纳，生成回答并附引用来源链接。首期单轮问答即可。
- **FR-9 后台管理页**：管理员账号密码登录（首次登录强制改密），后台包含：仪表盘（文章总量、今日新增、采集/推送状态、AI 处理队列）；「立即采集」「重新生成今日日报」手动触发；采集日志与失败源告警；配置项：大模型 API Key、采集频率、每日 AI 处理上限、写入 API Token 的生成与重置。
- **FR-10 开放写入 API**：提供 REST 接口 `POST /api/v1/news`，Bearer Token 鉴权（Token 在后台生成/重置）。支持单条与批量（JSON 数组）推送；必填字段：标题、原文链接（url），可选：来源、发布时间、正文片段、标签；服务端执行 URL 规范化去重后进入 AI 处理管道；响应返回写入/重复计数与文章 id；带简单限速（如 60 次/分钟）防止滥用。


## 7. 关键流程 / 交互描述

**采集-处理流程（每日自动）：**
1. 定时任务触发 → 遍历所有启用信息源（HTTPS 请求经 subprocess 调 curl）
2. 解析出候选文章 → URL 规范化去重 → 新文章入库（状态 = pending）
3. 后台队列逐条调用大模型 → 生成摘要/标签/评分 → 状态 = done；失败 → 重试 3 次 → 仍失败标记 failed
4. 当日处理完成后 → 触发日报生成任务

**本地推送流程：**
1. 用户本地任务调用 `POST /api/v1/news`（携带 Token）→ 服务器校验 Token（无效返回 401）
2. URL 规范化去重 → 新文章入库（状态 = pending）→ 进入 AI 处理管道（同每日流程第 3 步）
3. 推送响应返回写入/重复统计，供本地任务核对

**用户浏览流程：**
1. 打开网站 → 首页默认展示最新日报 + 今日文章流
2. 通过排序/筛选/搜索缩小范围 → 点击文章卡片跳转原文

**智能问答流程：**
1. 用户输入问题 → 系统检索本地文章库（标题/摘要/标签关键词匹配）
2. 命中文章片段 + 问题 → 大模型生成回答 + 引用来源链接列表

## 8. 风险与依赖

**风险：**
- 服务器仅 1.7G 内存且已有多个服务（safebox:8090、bingzhi:1314 等），须严格限制进程内存；前端建议本地构建后上传静态产物
- 服务器 Python 3.11 源码编译缺 _ssl 模块：所有 https 网络请求必须走 subprocess + 系统 curl，这是全局架构约束
- 社交平台（Twitter/X、YouTube）无稳定免费采集途径，首期可能仅部分可用
- 大模型 API 存在成本与限流风险：需设置每日 AI 处理上限（建议 ≤50 篇/日），优先处理高重要性文章
- CentOS 7 已停止维护，软件源受限，尽量复用已有 Python 3.11 与系统工具
- 写入 API 面向公网开放：必须 Token 鉴权 + 限速，否则会被恶意灌水
- 公开访问后流量可能增长，1.7G 内存服务器需考虑页面缓存/静态化降低后端压力
- 广告平台（如 Google AdSense）通常要求独立域名，纯 IP 访问难以通过审核

**依赖：**
- 大模型 API（任选一家 OpenAI 兼容接口服务，Key 由用户配置于 .env）
- 云服务器（CentOS 7）：新项目必须用 /study/env/python3.11/bin 的 Python 创建独立 venv；部署新端口（避开 8090/1314）；nginx 反向代理配置位于 /usr/local/nginx/conf/conf.d/
- 各信息源 RSS 可用性（机器之心、量子位等中文媒体 RSS 不稳定时，需准备官网 curl 抓取备选方案）

## 9. 验收标准

- [ ] 网站公开可访问（访客免登录浏览），首页展示最新日报与今日文章列表
- [ ] 后台管理页需账号密码登录，未登录无法访问管理功能
- [ ] `POST /api/v1/news` 携带有效 Token 推送成功入库；错误 Token 返回 401；重复 URL 返回重复计数
- [ ] 页面视觉与交互达到精品水准
- [ ] 定时任务每日自动执行采集，新文章入库且 URL/标题去重生效
- [ ] 每篇新文章自动生成中文摘要、至少 1 个分类标签、1-5 重要性评分
- [ ] 每日日报按日期自动生成，历史日报可回看
- [ ] 所有 HTTPS 抓取通过 subprocess 调 curl 实现，无 ssl 模块报错
- [ ] 智能问答能针对已采集内容给出回答并附来源链接
- [ ] 管理页可手动触发采集与日报生成，可查看采集日志与失败告警
- [ ] 所有密钥通过 .env/环境变量配置，代码与文档中不出现明文密码
- [ ] 服务部署在独立 venv，内存峰值 < 500MB，与服务器既有服务共存正常
- [ ] 手机浏览器访问排版正常
